# 日序：产品设计与后续路线

## 产品判断

多 Agent 时代，人的主要瓶颈是注意力与验收：有些任务自己在做，有些交给 Agent 执行，还有一些等待自己查看结果。因此主界面仍然围绕「一天」和三个明确状态展开。执行者、等待反馈和关联链接作为任务属性，避免再引入一组互相冲突的主状态。

## 已落地的设计（v0.2.1）

| 使用情境 | 对应功能 | 设计理由 |
| --- | --- | --- |
| 今天要做什么 | 按日列表、周日期条、月历 | 既能专注当天，也能提前安排 |
| 多个 Agent 同时工作 | 执行者、Agent 协作视图 | 快速区分自己的行动与委派事项 |
| Agent 做完但人还没验收 | 等待反馈标记、关联链接 | 保留验收这一步，不自动算完成 |
| 一个任务过大 | 可折叠子步骤、备注 | 把下一步写清楚，减少重新进入任务的成本 |
| 任务在多台设备修改 | 版本校验、冲突保留 | 不以设备时钟判断胜负，避免离线内容丢失 |
| 网络不好 | 本机先保存、重连补传 | 录入不依赖云端响应 |
| 任务误删 | 可恢复回收站 | 删除通过墓碑同步，其他设备也能恢复 |
| 数据迁移 | JSON 导入导出 | 可独立保存和转移个人数据 |
| 多任务快速切换 | 拖拽改状态和排序、触控与键盘操作 | 减少进入编辑窗口的次数 |
| 边工作边看任务 | 精简小窗口、Windows 置顶和最小化 | 在有限屏幕空间保留当前行动 |
| 完成后找不到产出 | 文档与项目文件夹关联 | 任务完成记录连接到可打开的成果 |
| 手机临时查文档 | 逐项手动上传私有副本 | 默认保留在本机，按需开放同账号跨设备查阅 |
| 临时碰到电脑小故障或琐事 | 计划任务 / 零碎问题类型、图标和颜色区分、类型筛选 | 避免小问题混入主要工作而难以辨认；类型与紧急程度分别记录 |

界面使用暖白、鼠尾草绿和深绿色，主要内容采用纵向列表。桌面端侧栏承担导航和月历，右栏只保留当天进度和下一件重点；小屏幕收起两侧区域，底部提供主要导航。交互元素使用原生语义标签，弹窗使用原生 dialog 管理焦点与 Escape。

## 建议的下一阶段

1. **全局快速捕获**：全局快捷键弹出轻量输入框，支持「明天 / 下周一」日期解析。先保证可靠保存，再考虑接入语义模型。
2. **Agent 交付收件箱**：通过授权 Webhook 接收任务完成事件。完成事件默认进入「等待验收」，由人确认质量后结束任务。
3. **依赖与阻塞**：增加「等待某任务」关系，标示阻塞原因；主状态保持三种，避免状态无限扩张。
4. **每日收尾**：每天手动查看未结束事项，选择移到次日、改期或取消；迁移应明确显示，不悄悄滚动历史任务。
5. **循环任务与提醒**：以独立实例生成每日任务，历史完成情况可追溯。提醒需分平台测试后台、休眠、时区和重复通知。
6. **模板与批量拆解**：保存论文阅读、PR 验收、组会准备等步骤模板，支持从 Markdown 清单批量创建。
7. **搜索与归档扩展**：当任务数量增长后，分页加载全部任务、全文索引和列表虚拟化，避免一次渲染全年记录。
8. **专注时段**：可选轻量计时，与任务关联；不强制排名、连续打卡或制造每日负担。

## 技术取舍

- Tauri 复用系统 WebView2；不打包完整 Chromium。安装包大小与启动表现以实际构建测量为准，不预先承诺内存占用。
- 同一任务及子步骤作为一个原子文档提交。两个设备分别修改不同子步骤时，首版仍视为同一任务的冲突，优先保全数据；更细的自动合并可后续评估。
- 首版每次同步分页读取账号任务以保证删除墓碑和漏掉的事件能恢复；这适合个人规模。大量历史记录应改为服务端增量游标与分页归档。
- 本机操作与云端确认共用串行写队列，先完成 IndexedDB 事务再更新展示；云端请求有超时，并在断网时取消进行中的请求。
- Android 原生打包、网页托管和系统级提醒需要分别验证，响应式界面不等同于已经发布这些平台。
- Windows 产出使用本机路径登记表，任务同步只带附件标识和名称；网页副本放 IndexedDB。文件内容只走用户明确点击的 Storage 上传，不进入任务自动同步队列。
- 云端副本是独立快照；文件夹打包在后台完成并限制 25 MB / 2000 项。暂不监听文件系统变化、不自动压缩大型项目、不自动上传源码或隐藏文件夹。
